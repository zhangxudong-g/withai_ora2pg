# 阶段 4：构建 Agent + Skill 迁移能力

## 1. 阶段目标

构建能够辅助 Oracle → PostgreSQL 迁移的 Agent 和 Skill，使其能够分析源码、识别风险、调用转换工具、生成修正方案和验证用例。

Agent 的职责不是盲目自动改写，而是基于证据完成可追踪的迁移辅助工作。

## 2. 主要任务

### 2.1 明确 Agent 的职责边界

Agent 可以负责：

- 分析迁移对象
- 识别 Oracle 特有语法
- 分析依赖关系
- 检索转换规则
- 调用脚本或 SQLines
- 解释转换差异
- 生成 PostgreSQL 修正建议
- 生成验证用例
- 执行允许的验证命令
- 输出风险和人工确认项

Agent 不应：

- 编造不存在的源码内容
- 在没有证据时判断业务语义
- 静默覆盖原始文件
- 对高风险逻辑进行无确认修改
- 将未执行的验证描述为已验证

### 2.2 设计工具集

建议工具包括：

- list_files：列出项目文件
- search_code：搜索表名、函数名、关键字和调用关系
- read_code：读取源码
- analyze_object：分析数据库对象
- analyze_dependencies：分析依赖关系
- convert_with_script：调用现有转换脚本
- convert_with_sqlines：调用 SQLines
- inspect_conversion：检查转换结果
- generate_test_case：生成验证用例
- execute_sql：执行安全范围内的 SQL
- compare_result：比较结果
- write_report：生成迁移报告

### 2.3 设计 Skill

可拆分为：

1. Oracle 对象分析 Skill
2. SQL 语法转换 Skill
3. PL/SQL 结构转换 Skill
4. Oracle 函数替换 Skill
5. Package 迁移 Skill
6. 动态 SQL 分析 Skill
7. 迁移风险识别 Skill
8. PostgreSQL 验证 Skill
9. 测试用例生成 Skill
10. 迁移报告生成 Skill

每个 Skill 应明确：

- 适用场景
- 输入
- 前置条件
- 操作步骤
- 可调用工具
- 输出格式
- 失败处理
- 风险提示
- 禁止行为

### 2.4 建立证据驱动的分析流程

建议流程：

1. 接收迁移任务。
2. 确认目标对象和范围。
3. 检索并读取相关源码。
4. 收集依赖和上下文。
5. 识别 Oracle 特性。
6. 选择转换策略。
7. 调用脚本或 SQLines。
8. 检查转换结果。
9. 对复杂部分进行语义分析。
10. 生成修正建议。
11. 生成验证用例。
12. 执行可执行验证。
13. 输出结果、风险和未确认事项。

### 2.5 设计输出格式

每次 Agent 执行应输出：

- 任务摘要
- 分析对象
- 使用的源码和证据
- 识别出的 Oracle 特性
- 采用的转换方式
- 自动转换结果
- 人工修正建议
- 验证用例
- 已执行的验证
- 未执行的验证
- 风险清单
- 最终状态

### 2.6 增加日志和审计

记录：

- 用户请求
- Agent 每一步操作
- 工具调用参数
- 工具返回结果
- 使用的规则或 Skill 版本
- 文件变更
- 验证命令和输出
- 最终结论

建议使用 JSONL 记录执行过程，便于问题追踪和复盘。

## 3. 主要产出

- Agent 总体设计
- Skill 目录和规范
- 工具接口定义
- Prompt 和输出模板
- 迁移执行流程
- 风险报告模板
- JSONL 执行日志
- 安全操作和权限控制方案

## 4. 完成标准

- Agent 能够基于源码证据工作。
- 每个关键结论都能追溯到源码、工具结果或执行日志。
- 高风险操作有明确提示和确认机制。
- 工具失败时能够停止、重试或转人工处理。
- 输出结果可以供工程师复核和继续修改。
