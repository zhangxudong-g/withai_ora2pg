# 阶段 5：典型案例端到端 PoC

## 1. 阶段目标

选择具有代表性的 Oracle 对象，验证“源码分析 → 转换 → 修正 → PostgreSQL 执行 → 结果验证 → 报告生成”的完整流程。

本阶段重点不是数量，而是验证整个迁移流程是否可执行、可复用、可审计。

## 2. 主要任务

### 2.1 选择 PoC 案例

至少包含：

- 简单 Function
- 包含多表查询的 Function
- 复杂嵌套 SQL
- 动态 SQL Procedure
- 使用 DBMS_SQL 的 Procedure
- 包含多个子程序的 Package
- 包含异常处理和事务控制的对象
- 包含 DML 和数据变更的对象

案例应覆盖不同复杂度和不同风险等级。

### 2.2 建立案例基线

每个案例记录：

- 源文件路径
- 对象名称
- 对象类型
- 依赖对象
- 输入参数
- 输出参数或返回值
- 数据变更范围
- 异常处理方式
- 关键业务规则
- 已知限制

### 2.3 执行完整迁移流程

按照统一流程执行：

1. Agent 读取和分析源码。
2. 识别对象结构和依赖。
3. 识别 Oracle 特性。
4. 调用现有脚本或 SQLines。
5. 检查自动转换结果。
6. 生成需要人工确认的差异。
7. 由 Agent 生成修正建议。
8. 生成 PostgreSQL 版本。
9. 在 PostgreSQL 中创建对象。
10. 执行正向、边界和异常测试。
11. 记录执行结果。
12. 生成案例报告。

### 2.4 设计人工复核节点

以下情况必须人工复核：

- 业务语义无法从源码确定。
- 动态 SQL 拼接逻辑复杂。
- DBMS_SQL 行为无法直接映射。
- Package 状态或初始化逻辑存在差异。
- 事务边界发生变化。
- 异常处理行为发生变化。
- 数据类型转换可能造成精度或范围损失。
- 结果集顺序或 NULL 行为可能变化。

### 2.5 验证测试结果

检查：

- 对象是否成功创建。
- 输入参数是否正确处理。
- 返回值是否符合预期。
- 查询结果是否正确。
- DML 影响行数是否一致。
- 异常是否在预期条件下触发。
- 事务提交和回滚是否符合要求。
- 性能是否存在明显退化。

### 2.6 复盘问题并形成改进项

对每个 PoC 记录：

- 失败原因
- 工具限制
- Prompt 限制
- Skill 缺陷
- 转换规则缺陷
- 验证环境缺陷
- 需要人工处理的工作量
- 是否可以沉淀为通用规则

## 3. 主要产出

- 端到端 PoC 案例
- 转换前后源码
- 修正记录
- 验证脚本和测试数据
- 执行日志
- 案例迁移报告
- 问题清单和改进计划
- 可复用规则和 Skill

## 4. 完成标准

- 至少完成若干不同类型的典型对象。
- 每个案例都有完整的转换和验证记录。
- 明确哪些步骤可以自动化，哪些必须人工参与。
- 能够识别 Agent 在真实迁移场景中的不足。
- PoC 结果能够指导后续全量迁移。
