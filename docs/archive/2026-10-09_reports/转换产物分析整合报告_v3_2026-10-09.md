## 二、冲突点与过时点的逐项核实（以当前产物实测为准）

### 2.1 TRIGGER —— ISSUES 的根因描述已过时，v1 正确
- 实测 `TRIGGER/00_TRIGGER.sql`：**BEGIN/END IF/RETURN NEW/$$ 结构完整**，ISSUES 所述"END IF 缺失、RETURN NEW 位置错误、缺 $$"在当前文件中**不存在**。
- 当前真实缺陷是第 2 行残留 `STUDENT_MST.STUDENT_NO%TYPE`。plpgsql 延迟解析使其**安装成功**（最新 L3: TRIGGER 1/1 通过），但**首次 INSERT STUDENT_MST 即运行期报错**。
- 这正是 v1 强调的核心教训：**L3 安装通过 ≠ 可用**。ISSUES 按"安装失败清单"定位问题，天然看不见这类"装上了但一调就炸"的对象。

### 2.2 PROCEDURE OUT 参数 —— ISSUES 的 P2-1 已修复
- 实测 `PROCEDURE/00_PROCEDURE.sql`：`o_nRTN` 已声明为 `INOUT o_nRTN NUMERIC`（SP_PROCESS_SCORE/SP_GEN_SCORE_REPORT/SP_BATCH_IMPORT_SCORE 均如此）。
- 但引入了新问题：INOUT 参数 + 函数式 RETURN 混用导致 `VALIDATE_SCORE_VALUE` 报"在带有输出参数的函数中 RETURN 不能有参数/结果类型必须是 numeric"——属于修复不彻底而非未修复。

### 2.3 一批 ISSUES P0/P1 问题在当前产物中已消失（文档基于旧快照）

### 2.4 v1 的两处小误差（一并修正）
- ~~"V_DEPENDENCY_GRAPH (+) 丢失"~~：实测该视图已无 (+) 问题（且 GROUP BY 字面量问题也不存在）。当前 VIEW 唯一失败对象是 **V_STUDENT_SCORE**。

### 3.3 整合后的问题清单（去重、纠偏、重新定级）

**P0（阻塞一键安装/静默错数据）**
1. **包全局变量机制整体失效**：赋值被拼成 `BEGIN set_config(...)`（语法错误），读取用 `current_setting()` 返回 text 参与数值比较（隐式类型风险）。取代了 ISSUES P0-1 的旧表述，是当前 PACKAGE_BODY 一半以上失败的根源。
2. **%SUBQUERY 占位符未回填**（SP_BATCH_IMPORT_SCORE 等）——不报错、静默丢数据，比语法错误更危险。
3. **嵌套子程序文本内联产生结构性坏代码**（INLINED 残骸、变量丢失 i_vsql/v_score、函数体粘连）——对应 ISSUES P1-1，仍未解决。
4. **(+) 外连接改写算法错误**（V_STUDENT_SCORE）——非简单残留，而是"改写错乱"。
5. **BULK COLLECT/FORALL/PIPE ROW/UTL_FILE 原样残留**——批量绑定与流式管道完全未迁移。

**P1（安装可过但首调即败 / 功能残缺）**
6. %TYPE 残留（TRIGGER、F_GET_CONFIG_VALUE、PKG 内多处）。
7. PACKAGE 12 处 TODO 空壳桩。
8. 序列同义词视图化后 NEXTVAL 失效。
9. INOUT+RETURN 混用、游标变量带参调用（CUR_ALL_STUDENT(...)）。

**P2（需业务确认/低危）**
10. GTT 语义、SEQUENCE MAXVALUE 封顶、SYNONYM→VIEW 权限面变化。
