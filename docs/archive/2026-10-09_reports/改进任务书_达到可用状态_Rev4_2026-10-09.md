## 二、总体架构决策（与依据报告一致）

把现有三条路线收敛为一个明确分工，全部落在 `/workspace` 内：

```
oracle_poc/01.SQL (Oracle 源)
   │
   ├─[规则直通区] perlstyle_engine ──► TABLE / SEQUENCE / DATA / 简单 VIEW      （已达标，保持）
   │        ▲ 仅修 3 个系统性 Bug：%SUBQUERY 回填(T3)、(+) ANSI JOIN(T4)、%TYPE 查表(T5)
   │
   ├─[AST 升级区] pipeline/parsers (ANTLR4, 需先装运行时 T7) ──► MigrationMetadata
   │        ├─ TRIGGER 重建（T8）
   │        └─ TYPE 对象类型→PG composite/函数/数组重设计（T9）
   │
   └─[AI Agent 区] pipeline/stages/stage3_ai ──► FUNCTION / PROCEDURE / PACKAGE_BODY 复杂体
            ├─ 嵌套子程序：禁用文本内联 → package_body_converter 提升为顶层函数（T10）
            ├─ TODO 桩：package_body_agent_integrator 喂给 Agent 逐段转换（T11）
            └─ BULK COLLECT/FORALL、PIPE ROW、UTL_FILE、自治事务：Agent 出方案 + 人工确认（T12）

产出统一写回 oracle_poc/output/，由 L1–L4 + L3.5 门禁把关（T1/T2），最后跑等价用例（T13）。
```

**路由策略**：复杂度低走规则（快、稳）；含 AST 可解析的语义结构走 AST；规则/解析搞不定的复杂体走 AI Agent（带 `validate_pg` 硬校验 + 重试回灌）。

#### T3. `%SUBQUERY%d%` 占位符回填兜底（数据丢失级 Bug） 【P0】

**涉及文件**：

**实施步骤**：
1. 在 `perlstyle_engine.py` 找到最终输出前的位置（搜 `%SUBQUERY` 找到提取位置），插入：
   ```python
   def _assert_no_unresolved_placeholders(self, text: str) -> str:
       pattern = re.compile(r'%SUB(?:QUERY|PARAMS|PART|OUTERJOIN)\d+%')
       unresolved = pattern.findall(text)
       if unresolved:
           self.warnings.append(f"UNRESOLVED_PLACEHOLDERS: {unresolved} — falling back to original subquery text")
           # 方案 B：放弃占位符优化，从 self._original_subqueries 还原
           for ph in set(unresolved):
               key = ph.strip('%')
               if key in self._original_subqueries:
                   text = text.replace(ph, f"({self._original_subqueries[key]})")
               else:
                   # 无法还原则报错（绝不静默放行）
                   raise ConversionError(f"Cannot resolve placeholder {ph} and no original text cached")
       return text
   ```
2. 改造 `_extract_subquery` 路径：在抽取时同步把原文存进 `self._original_subqueries[ph_name] = orig_text`
3. 加单测（`pipeline/tests/test_subquery_restore.py`）：
   - `test_merges_using_subquery_restore` — 输入 `MERGE INTO t USING (%SUBQUERY0%)`，断言产出 `USING (SELECT * FROM s WHERE ...)`
   - `test_unresolvable_placeholder_raises` — 故意构造无原文的占位符，断言抛 `ConversionError`

- 风险 1：原始子查询含有占位符链式引用。**对策**：抽取时深拷贝并清空已用占位符

   ```python
       where_conds = extract_where_conditions(sql)  # [Condition, ...]

       graph = self._build_join_graph(from_tables, where_conds)
       # 3) 以"无 (+) 出边的表"为驱动表做拓扑
       join_plan = self._topological_join_plan(graph)
       # 4) 生成 ANSI JOIN 链
       return self._render_ansi_joins(join_plan)
   ```
2. `extract_from_tables` / `extract_where_conditions` 用 `sqlparse`（pglast 的兄弟库，已在依赖中）+ 自写 regex 兜底
3. `topological_join_plan` 算法：
   - 节点=表别名；边=等值条件；带方向（保留侧/外侧）
   - 起点：所有出边无 (+) 的节点
   - 用 Kahn 算法：依次输出度为 0 的节点，其边的目标节点入度-1
   - 无法归入任何 JOIN 的 (+) 条件：降级为原样保留 + warning（**宁缺勿错**）
4. 在 `perlstyle_engine.py` 的 `OUTERJOIN` 占位符回填段，把当前简单 regex 替换为 `OuterJoinRule.convert()` 调用
5. 加 golden 样例：4 表（student/subject/score/teacher）的 (+) 测试 + 经典 Oracle 三表 (+) 测试

   - 7 个 fixture（覆盖：1:1 简单外连接、多表 (+) 链、复杂混合、无 (+) 降级、无法归约报错）
   - 每个 fixture 跑 `convert()` 并 diff 期望产物
