# 阶段 1：建立转换基准与验证框架

## 1. 阶段目标

建立 Oracle → PostgreSQL 迁移的统一基准、案例集和验证方法，明确什么叫“转换成功”和“迁移正确”。

本阶段不追求立即完成大规模转换，而是先构建后续脚本、SQLines、LLM Agent 都可以复用的验证基础。

## 2. 主要任务

### 2.1 明确迁移范围

- 明确需要迁移的对象类型：
  - Table
  - Index
  - Constraint
  - Sequence
  - View
  - Function
  - Procedure
  - Package
  - Trigger
  - 定时任务或相关配置
- 明确暂不处理或需要人工确认的对象。
- 区分数据库对象迁移、数据迁移、业务逻辑迁移和应用侧 SQL 迁移。
- 建立对象清单及迁移状态字段。

### 2.2 建立典型 SQL / PL/SQL 案例集

选择能够覆盖主要语法和业务风险的案例，至少包括：

- 基础 SELECT
- 多表 JOIN
- OUTER JOIN
- 子查询和相关子查询
- EXISTS / NOT EXISTS
- UNION / UNION ALL
- GROUP BY / HAVING
- 分析函数
- ROWNUM / 分页
- 日期和时间处理
- NULL 处理
- DECODE / NVL / NVL2
- CASE 表达式
- MERGE
- INSERT INTO SELECT
- UPDATE / DELETE with subquery
- 动态 SQL
- REF CURSOR
- DBMS_SQL
- Function
- Procedure
- Package
- Exception handling
- 事务控制
- 临时表或集合类型（如有）

### 2.3 建立覆盖矩阵

为每个案例记录：

- Oracle 语法特性
- 业务目的
- 依赖的表和字段
- 输入条件
- 预期输出
- 转换难点
- 目标 PostgreSQL 写法
- 是否需要人工改修
- 验证方式
- 风险等级

建议风险等级：

- 高：可能导致结果错误、数据损坏或事务语义变化
- 中：语法可转换，但需要确认行为差异
- 低：规则明确且容易自动验证

### 2.4 定义验证层次

建立多层验证标准：

1. 语法验证：目标 SQL 是否能够解析或执行。
2. 对象验证：函数、过程、表和约束是否成功创建。
3. 结果验证：相同输入下结果是否一致。
4. 边界验证：NULL、空集合、极值、重复数据、日期边界等。
5. 异常验证：异常触发条件及异常处理行为是否一致。
6. 数据变更验证：INSERT、UPDATE、DELETE、MERGE 的影响行数和最终数据。
7. 事务验证：COMMIT、ROLLBACK、异常时回滚范围。
8. 性能验证：执行计划、执行时间、索引使用和资源消耗。

### 2.5 设计测试数据

- 准备正常数据。
- 准备空数据。
- 准备重复数据。
- 准备 NULL 数据。
- 准备边界日期和数值。
- 准备大数据量场景。
- 准备违反约束或触发异常的数据。
- 记录每组数据的用途和预期结果。

### 2.6 建立基线记录格式

每个案例至少保存：

- 案例编号
- Oracle 原始 SQL / PL/SQL
- Oracle 预期行为或已知结果
- 转换工具及版本
- 转换后的 PostgreSQL 内容
- 手工修正记录
- PostgreSQL 执行结果
- 差异说明
- 风险判断
- 最终结论

## 3. 主要产出

- 迁移对象清单
- 典型 SQL / PL/SQL 案例集
- 语法覆盖矩阵
- 风险分类标准
- 测试数据集
- 验证用例模板
- 转换结果基线模板

## 4. 完成标准

- 典型案例覆盖主要 Oracle 特性。
- 每个案例都有明确的输入、输出和验证方式。
- 后续不同转换方案可以使用同一套案例进行比较。
- 能够区分"语法转换成功"和"业务行为一致"。
