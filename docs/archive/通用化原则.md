# Oracle→PostgreSQL 通用化原则

> 创建于 2026-09-17
> 适用范围: 本仓库所有 PL/SQL → PL/pgSQL 转换器代码

---

## 1. 核心原则 (THE PRINCIPLE)

**通用转换器必须能处理所有 Oracle PL/SQL 模式。禁止为单个对象编写特殊处理函数 (special handler)。**

理由:
- **可维护性**: 每个特殊 handler 是孤立的知识, 难发现、难复用、难验证一致性
- **可移植性**: 转换器与项目深度耦合, 无法用于其他 Oracle 数据库
- **诚实性**: 特殊 handler 常以"存根"形式掩盖"业务逻辑未实现"的事实

具体规则:
1. **禁止新增 `convert/plsql_special_handlers.py` 或类似的对象级特殊处理模块**
2. **禁止在 `convert_function()` 内部按对象名 (GKB*) 硬编码分支**
3. **禁止在 `.env` 之外的代码中包含 GKB/特定项目的表名、字段名、对象名**

例外 (允许):
- 通用规则引擎的 `convert_function()` 中按语法模式 (非对象名) 处理, 例如 `CURSOR c IS SELECT ... → FOR 循环`
- 环境变量配置 (`.env` 中) 用于项目特定的命名约定/类型映射
- 失败报告生成 (`conversion_report.py`) 用于诊断而非生成代码

## 2. 转换失败处理 (FAILURE HANDLING)

**无法转换时, 优先生成失败报告, 而非静默生成"存根"代码。**

报告输出: `out/plsql/REPORTS/<对象名>.md`

报告内容 (见 `convert/conversion_report.py`):
- 基本信息 (对象类型、源文件、失败时间、类别、阶段)
- 失败摘要 (原始错误)
- 根因分析
- 涉及的 Oracle 特性 (自动检测)
- 相关依赖 (FROM/JOIN/INSERT 引用的表)
- 建议手动操作 (按失败类别给出)
- 同类失败对象
- 源 SQL 摘录 (锚定错误位置/依赖表附近)
- 相关 DDL 摘录

失败类别 (FailureCategory):
- `SYNTAX` - 源 SQL 语法不被识别
- `TYPE_UNKNOWN` - 未映射的 Oracle 类型 (库里类型)
- `NESTED` - 嵌套子程序结构无法内联
- `ROWTYPE` - %ROWTYPE 参数/变量无法展开
- `CURSOR` - 具名游标/动态 SQL 无法转换
- `SEMANTIC` - 业务语义无法机械等价转换
- `DEPENDENCY` - 依赖外部库函数/库外类型
- `UNKNOWN` - 其他未知错误

报告生成触发点:
1. 转换过程中 `convert_function` 抛出异常
2. PG 加载产物失败 (运行 `scripts/diagnose_plsql_failures.py`)
3. `pg.py verify` 检测到 FAIL (在 verifier 内调用 `record_failure`)

## 3. 项目特定配置 (.env)

非通用配置 (项目特定命名约定/类型映射) 必须通过环境变量提供, 不在代码中硬编码。

`.env` 当前支持的变量:

| 变量 | 用途 | 示例 |
|------|------|------|
| `PG_SOURCE_BASE` | Oracle 源根目录 | `D:\JIP\poc\source` |
| `PG_FUNC_PREFIX` | 包函数命名前缀 | `gkbpkg` |
| `PG_ORACLE_SOURCE` | DDL 备用路径 | `D:\JIP\poc\gkb\01.release\...` |
| `PG_RET_COL_OVERRIDES` | 返回值列名覆盖 | `GKBFKZKGMGET=ret` |
| `PG_TYPE_FALLBACK` | 库里 Oracle 类型 → PG 类型 | `A_CONS_PRM=NUMERIC[],REF_CUR_DOUTAI=REFCURSOR` |

非 GKB 项目只需:
```bash
cp .env.example .env
# 在 .env 中设置 PG_SOURCE_BASE + 项目特定的 PG_TYPE_FALLBACK / PG_RET_COL_OVERRIDES
```

无需修改任何 `.py` 代码。

## 4. 通用引擎增强项 (按优先级)

来自 [docs/PLSQL转换失败分析报告_237-9.md](PLSQL转换失败分析报告_237-9.md) 的 P1 项目。
每项对应一个或多个失败报告, 是后续引擎增强的 TODO。

| ID | 增强项 | 解决的失败对象 | 状态 |
|----|--------|---------------|------|
| P1.1 | 多行嵌套子程序头识别 (`FUNCTION f(...)` / `PROCEDURE p(...)` 跨行签名) | GKBFKGZSHNT, GKBSBCHKLCSV, GKBSKGYMSHKK | TODO |
| P1.2 | `%TYPE`/`%ROWTYPE` 解析 (查 DDL 取真类型) | GKBFKHMCTRL | 部分完成 (有 `_resolve_pctype`, 仍需测试) |
| P1.3 | 未知类型显式报错 (`EXCEPTION`, 库里类型) | GKBFKHMCTRL, GKBFKGKCDGET 等 | 部分完成 (有 env 配置 + 报告分类) |
| P1.4 | REF CURSOR 别名 → 内建 `REFCURSOR` | GKBSBIDOIRCSV | 部分完成 (有 env 配置) |
| P1.5 | 具名游标 → FOR 循环重写 | GKBSKGYMSHKK | TODO |
| P1.6 | `LOCK TABLE` 透传 (PG 原生支持) | GKBFKHTCLR, GKBFKHTSET | 已透传, 产物仍因 NESTED 失败 |
| P1.7 | 主 BEGIN 深度计数定位 | GKBFKGZSHNT | TODO |

## 5. 验证与诊断

### 主流程 (与项目解耦)
```bash
# 转换
python pg.py convert plsql   # 通用引擎转换所有 PL/SQL

# 验证 (PG 加载 + 业务测试)
python pg.py verify all

# 失败诊断 (生成 out/plsql/REPORTS/*.md)
python scripts/diagnose_plsql_failures.py
```

### 解读失败报告
1. **TYPE_UNKNOWN 报告** → 在 `.env` 的 `PG_TYPE_FALLBACK` 添加该类型映射
2. **SYNTAX/NESTED 报告** → 反映为 `convert_function` 的引擎增强项 (P1.x)
3. **ROWTYPE 报告** → 增强 `_read_ddl_columns` 风格的展开
4. **DEPENDENCY 报告** → 需要在源 DDL 中补充该类型/对象
