# 快速适配指南：将工具用于其他 Oracle 项目

## 1. 项目结构准备

```
your_project/
├── source/
│   ├── table/          # *.SQL - 表 DDL
│   ├── function/      # *.SQL - 独立函数
│   ├── procedure/     # *.SQL - 独立过程
│   ├── view/          # *.SQL - 视图
│   └── package_body/  # *.SQL - 包主体
└── out/               # 转换输出
```

## 2. 必改配置

### 2.1 修改 `convert/convert_package_body.py` 源路径

```python
# 第 391 行
# 改前:
_base = pathlib.Path(__file__).resolve().parent.parent / 'gkb' / '01.release'

# 改后:
_base = pathlib.Path(__file__).resolve().parent.parent / 'source' / 'package_body'
```

### 2.2 修改 `convert/convert_package_body.py` 函数命名

```python
# 第 618 行
# 改前:
pg_name = f"gkbpkg_{prefix}"

# 改后 (根据项目):
pg_name = f"pkg_{prefix}"
```

### 2.3 更新 `out/pkg_stubs.sql`

删除 GKB 特定的包桩，添加项目需要的外部包声明。

## 3. 可选配置

### 3.1 类型映射 (`convert/type_mapping.py`)

通常不需要修改，除非新项目有特殊类型。

### 3.2 复杂对象策略 (`convert/_complex_section.py`)

删除 GKB 特定配置，根据新项目需要添加。

## 4. 转换命令

```bash
# DDL
python convert/ddl_converter.py --all

# 独立函数/过程
python convert/plsql_converter.py --all

# VIEW
python convert/view_converter.py --all

# 包主体
python convert/convert_package_body.py --all

# 包桩
python convert/generate_pkg_stubs.py
```

## 5. 常见问题

### Q: REF CURSOR 报错？
A: 使用 `EXECUTE` 动态 SQL 替代

### Q: `%ROWTYPE` 不支持？
A: 改用显式类型声明

### Q: `(+)` 外连接报错？
A: 需要手动重写为 LEFT/RIGHT JOIN

### Q: 嵌套函数报错？
A: 展平为独立函数或改写为普通函数

## 6. 验证清单

- [ ] 所有 DDL 文件加载成功
- [ ] 所有 PL/SQL 对象创建成功
- [ ] VIEW 语法正确（可能有依赖警告）
- [ ] 业务逻辑测试通过

## 7. 工具局限性

以下场景需要手动处理：

| 场景 | 建议 |
|------|------|
| `CONNECT BY` 递归 | 改写为 `WITH RECURSIVE` |
| 复杂 `(+)` 外连接 | 手动重写 SQL |
| 自治事务 | 改用 `dblink` 或应用层处理 |
| 高级包特性 | 按功能拆分为独立函数 |
