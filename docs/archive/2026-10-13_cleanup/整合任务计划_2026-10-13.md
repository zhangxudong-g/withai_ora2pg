## ⚠️ 紧急插队：P4-2 lift 引入 `END ;;` 回归（2026-10-13 10:33 实测发现）

> **优先级高于本文所有其他任务。** 手动全链路执行后暴露：**79% 的 L3 安装失败是同一个根因**。

### 现象

```
python scripts/install_oracle_poc.py install
  [ 7/12] FUNCTION/00_FUNCTION.sql ... FAIL (exit=3)
     psql:.../FUNCTION/00_FUNCTION.sql:78: 错误:  语法错误 在 ";" 或附近的
  [STOP] 子文件失败 → 后续 5 个文件未跑        ← DoD-1 直接 FAIL
```

L3 安装：**成功 151 / 总计 243，失败 92**。失败明细归因：

| 错误 | 数量 |
|---|---|
| **含 `END ;;` 的对象** | **73（79.3%）** |
| `语法错误 "set_config"`（包全局变量仿真）| 4 |
| `语法错误 "IN"` | 3 |
| `语法错误 "FOR"`（FORALL/循环）| 2 |
| `语法错误 "COLLECT"`（BULK COLLECT 未转）| 2 |
| PIPE ROW 未转 → `RETURN 不能带有参数` | 2 |
| SPEC/BODY 返回类型冲突 | 2 |
| 其他 | 4 |

### 根因

产物 `FUNCTION/00_FUNCTION.sql:71-78`：

```sql
BEGIN
    v_SQL := ADD_STUDENT_COND(v_SQL, i_nSTU);
    ...
EXCEPTION
    WHEN OTHERS THEN RETURN NULL;
    END ;;          ← 多一个分号
$$;
```

PL/pgSQL 解析块结束符 `END;` 后遇到游离的 `;` → 「语法错误 在 ";" 或附近的」。

### 这是 **P4-2 引入的回归**，不是历史遗留

| 版本 | FUNCTION 文件 `END ;;` 数 | 对象数 |
|---|---|---|
| `f52a1ba`（P4-2c）| **0** | 16 |
| `ce4f630`（P4-2e，启用 lift）| **8** | 28 |
| `2810905`（P4-2h，当前）| **42** | 52 |

**交集验证**：FUNCTION 文件 38 个坏对象中，**21 个在转换报告的 `Lifted nested` 集合内**——
确认是 **lift 路径在拼装函数时多输出一个分号**，两条子路径（ANTLR 检测 / 正则检测的嵌套函数）都中招。

### 修复成本与收益

| | |
|---|---|
| 预计工作量 | **< 0.5 天**。`END <name>;`→`END;` 的剥离逻辑在 `perlstyle_engine.py:4154-4160`，但 **lift 走的是另一条拼接路径**，需顺着 `_lift_nested_subprograms` 的产物拼装处定位 |
| 预期收益 | **L3 失败 92 → 约 19**；DoD-1 一键安装从 FAIL 变为可跑通 |
| 复现方式 | `convert --clean` 后 `grep -n 'END\s*;;' oracle_poc/output/*/*.sql` |

> **这条排在 W0 之前。** 理由：W0 是"让问题可见"，这条是"把最大的那个洞补上"；
> 且它是**回归**——修它等于把 P4-2 造成的损失收回。

**建议编号**：**P4-2R**（回归修复），归入 P4-2 收尾，不单开新阶段。
