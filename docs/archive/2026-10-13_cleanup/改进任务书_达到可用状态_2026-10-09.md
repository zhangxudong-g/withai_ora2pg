### 两条方法论教训（不可违反）

> **教训一："能安装 ≠ 可用"**
> plpgsql 函数体**延迟解析** —— `CREATE FUNCTION` 不校验体内 SQL/列引用，只在首次调用时才完整解析。
> 因此 L3 全绿的对象可能一调就炸。**所有"安装成功"的对象必须再经 L3.5 首次调用冒烟才算通过。**
>
> **教训二："能转换 ≠ 没丢东西"**（DoD-7 的由来）
> DoD-2 只能查**残留**，查不出**缺失**。实测铁证：
> `TRIGGER/00_TRIGGER.sql` 源 **5238 字节 → 产物 883 字节（丢 83%）**，
> 而 `_conversion_report.json` 记 `success: true, warnings: []` —— **报成功、零警告**。
> **四层验证全都发现不了**，因为丢失的对象在产物里根本不存在，没有任何东西可报错。
> 根因：`ora2pg_py_perlstyle/perlstyle_engine.py:1978` 自注 *"Convert only the first trigger block"*。

#### T0. 静默丢失治理：多对象拆分 + 产出完整性断言 【P0·最高优先·排 D1】

> **为什么排第一**：这是当前**唯一会让 DoD-2/3/4/5 全部失效**的缺陷。
> 残留扫描只查"多出来的"，查不出"少掉的"；丢失的对象在产物里不存在，L1/L2/L3/L3.5 无从报错。
> **在其他任务开工前先堵这个洞**，否则后续修复的验证结果都不可信。

**现状证据（实测）**：

| 项 | 实测值 |
|---|---|
| 源 `01.SQL/TRIGGER/00_TRIGGER.sql` | **6 个触发器**：TRG_STUDENT_BI / TRG_STUDENT_AU / TRG_SCORE_BIU / TRG_SYSTEM_CONFIG_BD / TRG_SCORE_COMPOUND / TRG_V_STUDENT_IO |
| 产物 `output/TRIGGER/00_TRIGGER.sql` | **仅 1 个**（TRG_STUDENT_BI）—— 5/6 静默丢失 |
| `_conversion_report.json` 对该项的记录 | `success: true, error: "", warnings: []` ← **报成功、零警告** |
| 字节数 | `input_bytes: 5238` → `output_bytes: 883`（**丢 83%**）|

**根因**（`ora2pg_py_perlstyle/perlstyle_engine.py:1978-1981`，代码自注）：

```python
# Convert only the first trigger block present in the source text.
# Multi-trigger files are out of scope for this fix; subsequent
# triggers are left unprocessed (as before this change).
return _convert_single_trigger(sql)
```

- `_split_triggers()`（同文件 1942 行）**已实现**按 SQL*Plus `/` 行切分多触发器，但**从未被 `convert_trigger` 调用**
- 由 commit `1bbc132`（"fix: TRG_STUDENT_BI 触发器 BEGIN/END 深度感知提取"）引入：当时只修好第 1 个，其余 5 个**不处理却整体报成功**
- 全引擎扫描确认：`only the first` 类缺陷**仅此一处**，无同类扩散

**目标**：① 修好多触发器拆分；② 让"源有产物无"变成**硬失败**，杜绝再次静默。

**涉及文件**：
- 修 `ora2pg_py_perlstyle/perlstyle_engine.py:1955-1981`（`convert_trigger` 改为遍历 `_split_triggers` 结果）
- 修 `ora2pg_py_perlstyle/perlstyle_engine.py:4967` 附近的批量分发路径，确保多对象文件逐个下发而非整文件单发
- 扩展 `scripts/convert_oracle_poc.py`：转换报告新增 `dropped_objects` 字段；非空即 exit 1
- 新建 `docs/对象完整性基线.md`：记录 12 个产物文件的**源对象数 / 产物对象数**对照，作为 DoD-7 基线

**实施步骤**：
1. 在 `convert_trigger` 中恢复多对象支持：
   ```python
   def convert_trigger(sql: str) -> Tuple[str, List[str]]:
       blocks = _split_triggers(sql)
       if len(blocks) <= 1:
           return _convert_single_trigger(sql)
       out, warns = [], []
       for i, blk in enumerate(blocks):
           piece, w = _convert_single_trigger(blk)
           if not piece.strip():
               warns.append(f"trigger block #{i+1} 转换产出为空（原对象名待补）")
               continue
           out.append(piece)
           warns.extend(w)
       return "\n\n".join(out), warns
   ```
2. **加对象名兜底**：`_convert_single_trigger` 解析不出 header 时，**必须把该块的原对象名记入 warnings**，
   禁止静默返回原文（当前 1994-1995 行直接 `return result, ['Could not parse trigger header']`，会把整段原样透传）
3. 新增通用对象计数断言（`_assert_no_dropped_objects`）：转换前后按对象类型正则计数，数量减少即抛 `ConversionError`，
   与 T3 的 `_assert_no_unresolved_placeholders` 同款"绝不静默放行"策略
4. 扫描**其余 11 个产物文件**是否存在同类丢失（用第 3 步的计数断言跑全量，重点 PACKAGE / PACKAGE_BODY / TYPE 这类多对象文件）
5. 扩展转换报告 + `verify_oracle_poc_output.py`，把 `dropped_objects` 纳入 Gate

**目标**：把分析报告里手工用的正则固化为工具，任何残留即判 fail；接入 Gate 前置条件。

**涉及文件**：
- 新建 `scripts/scan_oracle_residuals.py`（约 250 行）
- 扩展 `workspace/verification/static_check.py`（**真源**；与 `pipeline/verification/` 那份同名文件哈希一致但**不被 Gate 读取**），复用 `patterns.py` 的 `RULE_GROUPS`
- 修改 `scripts/verify_oracle_poc_output.py`：在 L1 之前先跑扫描，major>0 直接 exit 1

**实施步骤**：
1. 定义模式表，结构 `[{"id": "RES-A", "pattern": r"%TYPE", "severity": "major", "whitelist": [...], "category": "A"}, ...]`，覆盖 DoD-2 全部模式
2. 实现 `_strip_comments`（已有，见 `patterns.py`）和 `_strip_strings`（**新增**，避免 `'%TYPE'` 字符串字面量误报）
3. 白名单机制：每条 pattern 可配 `whitelist: [r"(?<!REC_)SQLCODE"]` 等；支持"上下文相邻 5 行内 DDL 列定义"豁免
4. **TODO 规则须同时覆盖两种形态**：`/* TODO ... */`（16 处）与 `-- TODO ...`（12 处）。只匹配块注释会漏掉一半

       pattern = re.compile(r'%SUB(?:QUERY|PARAMS|PART|OUTERJOIN)\d+%')

       if unresolved:

**目标**：清剩余 C/E 类硬骨头，其中多数**需要业务决策**，Agent 出候选、人来拍板。

**涉及文件**：
- **改动落点**：`ora2pg_py_perlstyle/perlstyle_engine.py` 对应转换段
- 新建（**落 `workspace/`**）：`bulk_collect.py`（约 200 行）、`pipe_row.py`（约 150 行）、必要时 `transaction.py`
- `docs/迁移注意事项.md`（决策项登记）

**实施步骤（分项）**：

**(a) BULK COLLECT INTO t + FORALL i IN 1..t.COUNT**
- 首选整体重构为**一条集合 SQL**（`INSERT...SELECT` / `UPDATE...FROM` / `DELETE USING`，天然批量且更快）
- 确需逐行才用 `FOREACH x IN ARRAY t LOOP ... EXECUTE format(...)`
- 适用：SP_BATCH_IMPORT_SCORE、SP_BATCH_DELETE_SCORE、PROC_BATCH_*

**(b) PIPE ROW 管道函数 ×2**
- 重写为 `RETURNS SETOF student_record` + `RETURN NEXT` / `RETURN QUERY`，删游标样板
- 适用：F_GET_STUDENT_LIST_PIPELINE、F_GET_SCORE_LIST_PIPELINE

**(c) UTL_FILE（PROC_EXPORT_CSV）**
- 三选一：`\copy` 由应用层执行 / `COPY TO PROGRAM`（需 superuser）/ 封装 `file_fdw`
- **默认**：应用层导出，产物中先落成带说明的 stub

**(d) PRAGMA AUTONOMOUS_TRANSACTION + 函数内 COMMIT（FUNC_SETLOG）**
- 日志写入拆成独立 PROCEDURE（调用方自行提交）或 dblink 自治技巧
- `INOUT o_nVALUE + RETURNS` 冲突统一改 OUT 参数过程

**(e) 包全局变量 set_config 方案**
- 保留 `set_config('pkg.g_x', val, false)`（PG 原生）
- 修 `BEGIN set_config(...)` 拼接错误 → `PERFORM set_config(...)`
- 修 text/numeric 隐式比较 → `current_setting('x')::numeric`
- 未配置时用 `set_config` 初始化兜底 default

**DoD-2 验收**：
- 跑扫描器：`BULK COLLECT` / `PIPE ROW` / `UTL_FILE` / `EXECUTE IMMEDIATE` / `PRAGMA` 命中数 0
- L3 + L3.5：相关对象全绿

**风险与备选**：
- 风险 1：业务侧不能拍板 UTL_FILE。**对策**：保留 stub + 决策登记
- 风险 2：dblink 自治方案需 superuser。**对策**：决策项必须明确
- **默认决策（避免决策阻塞，业务方可后续推翻）**：
  - **UTL_FILE** → 应用层 `\copy` 导出 + 决策登记，不在转换器内实现
  - **PRAGMA AUTONOMOUS_TRANSACTION** → 拆为独立 PROCEDURE；dblink 仅作备选
  - **PG 版本** → 本期保持 PG 8.4，5 个无法实现的对象进 TODO；二期升 PG 13+ 后解锁

**预估规模**：L（2–4 天，含评审）

> **本节不包含在本次 T0–T15 实施范围**。达到**生产级别**所需的额外任务，另作二期任务书立项。**总工期 8–10 周**。
>
> 触发条件：T0–T15 全部达成 DoD-1～DoD-7 后，**项目发起人**明确启动二期。

| 任务 | 主题 | 预估 | 目的 |
|---|---|---|---|
| T16 | PG 版本升级到 13+ | 1 周（含数据迁移测试）| 解锁 COMMIT/ROLLBACK、改善错误处理、并行查询 |
| T17 | 批量数据迁移工具链 | 1.5 周 | 生产数据搬迁方案 |
| T18 | 性能基线与压测 | 1 周 | 转换产物的性能验收标准 |
| T19 | 可观测性（日志/追踪） | 1 周 | 生产排障能力 |
| T20 | Agent 确定性化 | 1.5 周 | 降低 LLM 不确定性，支持重复构建 |
| T21 | 真实项目回归（gkb 全量）| 2 周 | 验证通用性 |
| T22 | 其他语料回归 | 1–2 周 | 覆盖未覆盖语料 |
| T23 | 转换器产品化（CLI/配置化）| 1 周 | 非 POC 使用 |
| T24 | 文档与培训 | 0.5 周 | 交付给使用方 |
| T25 | 二期验收与总结 | 0.5 周 | 收尾 |

### 生产级别 5 维定义

| 维度 | 工程交付级（T0–T15）| 生产级别（T16–T25）|
|---|---|---|
| 安装 | 一键安装成功 | 一键安装 + 回滚脚本 + 版本化迁移 |
| 功能 | 主要功能等价 | 全功能等价 + 边界场景覆盖 |
| 性能 | 无要求 | 有压测基线与 SLA |
| 可运维 | 无 | 有日志/追踪/告警 |
| 可重复 | 手工触发 | CI 自动化 + 确定性构建 |
