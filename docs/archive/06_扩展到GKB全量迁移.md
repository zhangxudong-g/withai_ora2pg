# 阶段 6：扩展到 GKB 全量迁移

## 1. 阶段目标

在前期规则、验证框架和 PoC 结果基础上，分批推进 GKB 全量迁移，确保迁移过程可控、可回滚、可追踪。

## 2. 主要任务

### 2.1 建立全量对象清单

收集并分类：

- 表
- 字段
- 主键
- 外键
- 唯一约束
- 检查约束
- 索引
- 序列
- 视图
- Function
- Procedure
- Package
- Trigger
- 其他数据库相关对象

为每个对象增加状态：

- 未分析
- 已分析
- 待转换
- 已转换
- 待人工修正
- 已创建
- 已验证
- 验证失败
- 已确认
- 已完成

### 2.2 按依赖顺序迁移

建议顺序：

1. Schema 和基础配置
2. 类型和公共定义
3. 表结构
4. 序列
5. 主键和唯一约束
6. 基础索引
7. 数据迁移
8. 视图
9. Function
10. Procedure
11. Package
12. Trigger
13. 其他依赖对象
14. 应用侧 SQL 和配置

实际顺序应根据 GKB 的依赖关系进行调整。

### 2.3 迁移表定义

处理：

- Oracle 数据类型到 PostgreSQL 类型映射
- NUMBER 精度和范围
- DATE / TIMESTAMP
- CHAR / VARCHAR2
- CLOB / BLOB
- 默认值
- 虚拟列
- 标识列
- 主键和唯一约束
- 外键关系
- CHECK 约束
- 表和字段注释

对可能造成数据损失的映射必须人工确认。

### 2.4 迁移历史数据

制定数据迁移策略：

- 数据导出格式
- 字符编码
- NULL 处理
- 日期和时区处理
- 数值精度处理
- 大字段处理
- 批量提交策略
- 失败重试策略
- 增量或分批迁移策略
- 数据量统计

验证内容：

- 总行数
- 主键数量
- NULL 数量
- 汇总值
- 最小值和最大值
- 关联完整性
- 抽样记录
- 业务关键数据

### 2.5 迁移 PL/SQL 对象

按复杂度分批：

- 简单 Function
- 简单 Procedure
- 查询型对象
- DML 型对象
- 动态 SQL 对象
- 异常处理复杂对象
- Package
- Trigger

每个对象执行：

- 自动转换
- 静态检查
- 依赖检查
- 人工修正
- 创建验证
- 功能验证
- 风险确认

### 2.6 建立分批验证机制

每批迁移完成后验证：

- DDL 执行成功率
- 对象依赖是否完整
- 函数和过程是否可调用
- 关键 SQL 结果
- 数据完整性
- 事务行为
- 异常处理
- 性能和执行计划
- 应用侧兼容性

禁止在未完成上一批验证时无条件扩大迁移范围。

### 2.7 建立回滚和问题处理机制

准备：

- 迁移批次编号
- 变更清单
- 原始文件备份
- 转换后文件版本
- 数据备份或恢复方案
- 失败对象清单
- 回滚脚本
- 人工确认记录
- 变更审批记录

### 2.8 形成最终迁移报告

报告至少包括：

- 总对象数
- 已完成对象数
- 失败对象数
- 待人工处理对象数
- 数据验证结果
- 高风险差异
- 未验证范围
- 性能差异
- 遗留问题
- 后续运维建议

## 3. 主要产出

- GKB 全量迁移对象清单
- 分批迁移计划
- 表结构迁移结果
- 历史数据迁移结果
- PL/SQL 转换结果
- 验证报告
- 回滚和问题处理方案
- 最终迁移总结报告

## 4. 完成标准

- 所有迁移对象均有明确状态。
- 迁移批次可追踪、可复核、可回滚。
- 关键数据和业务逻辑完成验证。
- 高风险差异已由责任人确认。
- 未验证内容和遗留问题被明确记录。
- 具备进入试运行或正式切换的依据。
