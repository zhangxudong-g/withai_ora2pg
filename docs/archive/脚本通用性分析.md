## 脚本逐一评估

### 1. `convert/oracle_pg_rules.py` ✅ 通用 ★★★★★
- **状态**: 全新创建的通用 L1 规则库
- **覆盖**: NVL, DECODE, INSTR, SYSDATE, EXECUTE IMMEDIATE, DBMS_OUTPUT, RAISE_APPLICATION_ERROR 等
- **可用性**: 任何 Oracle 项目可直接 `from oracle_pg_rules import OraclePgConverter`

### 2. `convert/type_mapping.py` ✅ 通用 ★★★★★
- **状态**: 纯类型映射规则，无项目特定内容
- **覆盖**: 25 项 Oracle → PG 类型映射
- **改进**: 已可独立于 GKB 项目使用

### 3. `convert/type_converter.py` ❌ 已删除
- 无引用, 已删除 (功能在 `type_mapping.py` 内)

### 4. `convert/ddl_converter.py` ✅ 通用 ★★★★☆
- **状态**: 表 DDL 转换器
- **覆盖**: CREATE TABLE, 约束, 默认值
- **依赖**: 使用 `type_mapping.py`

### 5. `convert/view_converter.py` ✅ 通用 ★★★★☆
- **状态**: VIEW 转换器
- **覆盖**: FORCE, HINT, DECODE, COMMENT, 外连接标记

### 6. `convert/plsql_converter.py` ⚠️ 部分通用 ★★★☆☆
- **状态**: 独立 PL/SQL 函数/过程转换器
- **GKB 特定**:
  - 文档字符串中包含 GKBF/GKBS 示例名（仅注释）
  - `_complex_section` 导入（指向 GKB 特定配置）
- **通用部分**:
  - 参数解析、RETURN 类型转换
  - NVL → COALESCE, SYSDATE → CURRENT_DATE
  - 简单 SQL 重写规则

### 7. `convert/convert_package_body.py` ⚠️ 部分通用 ★★☆☆☆
- **状态**: PACKAGE_BODY 转换器
- **GKB 特定** (已修复):
  - ~~路径 `gkb/01.release`~~ → 已通过 `PG_SOURCE_BASE` 环境变量配置
  - ~~前缀 `gkbpkg_`~~ → 已通过 `PG_FUNC_PREFIX` 环境变量配置
- **改进**: 现在可通过环境变量适配其他项目

### 8. `convert/extract_subprograms.py` ❌ 已删除
- 无引用, 已删除 (功能由 `convert_package_body.py --all` 集成)

### 9. `convert/plsql_special_handlers.py` ❌ GKB 特定 ★☆☆☆☆
- **状态**: 8 个复杂对象的专用策略
- **完全 GKB 特定**: 函数名 (GKBFKGKCDGET 等) 硬编码
- **说明**: 这是 GKB 项目的专用配置, 其他项目不应使用
- **建议**: 重命名为 `gkb_special_handlers.py` 或移至 `config/gkb/`

### 10. `convert/_complex_section.py` ❌ GKB 特定 ★☆☆☆☆
- **状态**: 复杂对象转换策略
- **完全 GKB 特定**: 包含 8 个 GKB 复杂对象的策略配置
- **说明**: 与 plsql_special_handlers.py 类似, 应明确标记为 GKB 专用

### 11. `convert/generate_pkg_stubs.py` ✅ 通用 ★★★★☆
- **状态**: 外部包桩函数生成器
- **通用部分**: 桩函数生成逻辑与项目无关

### 12. `pg.py` ✅ 通用 ★★★★★
- **状态**: 统一 CLI 入口
- **特性**: convert/verify/info 子命令, 支持任意 Oracle 项目 (通过环境变量配置)

## 改进建议

### 优先级 P1 (立即修复)

1. **重命名 GKB 专用文件**:
   ```bash
   mv convert/plsql_special_handlers.py convert/gkb_special_handlers.py
   mv convert/_complex_section.py convert/gkb_complex_section.py
   ```
   这样其他项目使用者一眼就知道这些是 GKB 特定的。

2. **统一引用 oracle_pg_rules.py**:
   让所有脚本中的 L1 规则替换调用 `oracle_pg_rules.convert_sql()` 函数。

3. **文档化通用化限制**:
   在每个脚本顶部明确说明哪些部分通用、哪些项目特定。

### 优先级 P2 (后续改进)

4. **实现 SQLCODE/SQLERRM 映射**:
   ```python
   # 错误码映射示例 (基于文档 §8.6)
   ERROR_CODE_MAP = {
       'ORA-01400': '23502',  # NOT NULL violation
       'ORA-00001': '23505',  # Unique violation
       'ORA-02091': '40P01',  # Deadlock detected
   }
   ```

5. **添加 SQLines 规则表对照**:
   `OpenTool/sqlines-oracle-to-postgresql-rules.md` 的 199 行规则应该作为对照表加入 oracle_pg_rules.py。

### 优先级 P3 (L3 系统包)

6. **DBMS_SQL 重写框架**:
   根据文档 §11.1 的分析，提供通用重写框架。

7. **A_CONS_PRM 等库外类型处理**:
   通过配置文件指定外部类型映射。

## 新项目使用指南

### 最小成本方式（推荐）

```bash
# 1. 准备项目结构 (source/table, function, procedure, view)
# 2. 覆盖 Oracle 源路径与函数前缀
export PG_SOURCE_BASE=/path/to/your/oracle/source
export PG_FUNC_PREFIX=mypkg

# 3. 一键转换
python pg.py convert all

# 4. 验证
python pg.py verify all

# 5. 手工处理 (L2/L3 级别): 嵌套函数 / REF CURSOR / 复杂外连接
```
